Лабораторна робота №18 (Варіант 5): Власні винятки та патерн Result

Реалізація:
- OrderNotFoundException: власний клас винятку зі стандартними конструкторами та властивістю OrderId.
- Result<T>: узагальнений клас із полями IsSuccess, Value, Error та фабричними методами Success, Failure(string) і Failure(Exception).
- OrderService: метод GetOrder викидає OrderNotFoundException при відсутності замовлення; метод PlaceOrder повертає Result<bool>, якщо товару немає в наявності або дані некоректні.

Вивід програми:
=== 1. Пошук замовлення (GetOrder + OrderNotFoundException) ===
Знайдено замовлення #101: Ноутбук (1 шт.)
[Виняток] Замовлення з ID 999 не знайдено. (ID = 999)

=== 2. Оформлення замовлення (PlaceOrder + Result<bool>) ===
Замовлення #103 успішно оформлено.
[Result Failure] Не вдалося оформити замовлення #104: Товар 'Мишка' відсутній у потрібній кількості (доступно: 0).

Висновок:
Для методу GetOrder доцільно використовувати виняток OrderNotFoundException, оскільки звернення за неіснуючим ідентифікатором замовлення є порушенням очікуваного стану системи. Для методу PlaceOrder краще підходить патерн Result<T>, тому що відсутність товару на складі є штатним бізнес-сценарієм, який легко контролювати без накладних витрат на генерацію винятків.
