Самостійна робота №8: Узагальнений кеш Cache<TKey, TValue> із тестами

Опис реалізації:
Розроблено узагальнений клас Cache<TKey, TValue> з обмеженою ємністю та політикою витіснення найстаріших елементів FIFO (First In, First Out).
- Dictionary<TKey, TValue> забезпечує доступ, додавання та видалення елементів за ключем зі складністю O(1).
- Queue<TKey> відстежує хронологічний порядок додавання ключів для коректного витіснення найдавнішого елемента при заповненні кешу.
- Написано набір юніт-тестів у проєкті IndependentWork7.Tests (xUnit) для перевірки Add, Get, ContainsKey, Count, перевищення ємності та генерації KeyNotFoundException.

Приклад виводу консольної програми:
Додаємо 3 елементи (ємність = 3):
Кількість у кеші: 3
user_1 -> Олександр

Додаємо 4-й елемент (має витіснити user_1 за FIFO):
Кількість у кеші: 3
Чи є user_1 у кеші? False
user_4 -> Олена
Очікуваний виняток: Ключ 'user_1' не знайдено у кеші.

Відповіді на контрольні запитання:
1. Переваги узагальненого кешу: безпека типів на етапі компіляції, відсутність витрат на приведення типів і boxing/unboxing для значущих типів, можливість повторного використання коду для будь-яких пар ключ-значення.
2. Поєднання Dictionary та Queue: словник дає пошук і видалення за O(1), а черга зберігає порядок вставки і дозволяє миттєво отримати найстаріший ключ через Dequeue().
3. Коли кидати KeyNotFoundException, а коли використовувати TryGetValue: виняток доречний, якщо відсутність ключа є помилкою логіки програми; TryGetValue варто використовувати при штатних промахах кешу (cache miss), щоб уникнути накладних витрат на обробку винятків.
4. Критичні тести політики витіснення: переповнення кешу (capacity + 1) з перевіркою видалення найпершого ключа, перевірка незмінності Count == capacity, оновлення вже існуючого ключа без передчасного витіснення інших записів.
