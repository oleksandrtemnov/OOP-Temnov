1. Мета роботи
Поглибити розуміння життєвого циклу об’єкта в C#, навчитися працювати з некерованими ресурсами, реалізувати інтерфейс IDisposable та патерн Dispose.
2. Короткі теоретичні відомості
Життєвий цикл об’єкта: Охоплює створення (виділення пам'яті в купі), використання через посилання, збирання сміття (Garbage Collection) після втрати посилань та фіналізацію (виклик деструктора).
Керовані vs Некеровані ресурси: Керовані ресурси (пам'ять .NET) очищуються автоматично збирачем сміття (GC). Некеровані ресурси (дескриптори файлів, контексти малювання, сокети) потребують явного звільнення програмістом.
Інтерфейс IDisposable та оператор using: Інтерфейс дає метод Dispose() для явного звільнення ресурсів. Оператор using забезпечує гарантований виклик Dispose() при виході з блоку видимості, навіть у разі виникнення винятків (exception).
Патерн Dispose: Поєднує метод Dispose(), захищений метод Dispose(bool disposing) та деструктор ~ClassName(), гарантуючи безпечне очищення ресурсів.

4. Висновок
Під час виконання лабораторної роботи №3 було досліджено життєвий цикл об’єктів у середовищі .NET та реалізовано канонічний патерн Dispose для класу GraphicsContext.
Протестовано три підходи до керування ресурсами:
Використання using: Найнадійніший спосіб. Звільнення ресурсів відбулося детерміновано та автоматично одразу при виході з блоку видимості.
Явний виклик Dispose(): Дозволяє гнучко керувати ресурсом вручну, але вимагає від розробника самостійно стежити за викликом методу.
Неявне звільнення через GC: Для об'єкта, де Dispose() не був викликаний явно, збирач сміття автоматично підхопив об'єкт та запустив деструктор ~GraphicsContext(), який викликав Dispose(false) і безпечно звільнив некерований ресурс.
